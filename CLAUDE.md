# CLAUDE.md - Media Transfer conventions

macOS Electron 29 + React 18 + TypeScript app that offloads camera SD cards to an external SSD. Main process: `electron/` (bundled by esbuild to `dist-electron/`). Renderer: `src/` (Vite, built to `dist/`). Single user (Eddy), no network, no server.

## Never

- **Never touch real drives.** `/Volumes/tars` (Eddy's destination SSD), `/Volumes/SonyA6700`, `/Volumes/SonyZVE10`, and any other real card or disk (`Scratch1`, `TM-*`, ...) are never a test origin or destination. Tests use disposable disk images (rig below).
- **Never edit the packaged app's data:** `~/Library/Application Support/Media Transfer/` (`profiles.json`, `notifications.json`). A schema change migrates in place and keeps every profile.
- **Never change the copy/skip/verify logic** in `electron/transfer.ts` (`buildPlan`, `executePlan` and its helpers) without a work order and a Reviewer pass. The invariant: a file that already exists on the destination is never truncated, overwritten, renamed over or unlinked. The only files the app may replace or remove are the ones the **ownership ledger** (`userData/temps.json`) says it created: its `*.mtpart` temporaries and 0-byte placeholders. A name ending in `.mtpart` proves nothing. **Every destination open-for-write, rename and unlink goes through a `noClobber*` function in `electron/noclobber.ts`** (grep `noClobber`); nothing else in the code opens a destination path for writing.
- `build/icon.*` and the app identity (name, logo, palette) are Eddy's calls.

**Install gotcha (npm 11 / Node 26):** `npm install` skips dependency install scripts, so Electron's binary is never downloaded (`node_modules/electron/dist` holds only `LICENSES.chromium.html`), and running `node node_modules/electron/install.js` by hand extracts nothing on Node 26. Workaround: run the install script once so `@electron/get` caches the zip, then `ditto -x -k ~/Library/Caches/electron/<hash>/electron-v29.4.6-darwin-arm64.zip node_modules/electron/dist && printf 'Electron.app/Contents/MacOS/Electron' > node_modules/electron/path.txt`.

## Persisted files (dev path verified 2026-10-02 by a dismiss writing `notifications.json` there; packaged path per electron-builder `productName`, not re-verified)

`app.getPath('userData')` resolves from the package `name` in dev and from `productName` when packaged:

| File | Dev (`electron .`) | Packaged app |
|---|---|---|
| `profiles.json` `{ version: 1, profiles: { [volumeName]: Profile } }` | `~/Library/Application Support/media-transfer/` | `~/Library/Application Support/Media Transfer/` (sacred) |
| `notifications.json` `{ version: 1, items: [...] }`: `{ id, kind: "new-drive", volumeName, firstSeenAt, dismissedAt }` and (WO-3 A) `{ id, kind: "transfer-done" \| "transfer-failed" \| "transfer-cancelled", at, origin, destination, summary: { copied, verified, skipped, failed, failedNames (max 10), durationMs } }`, newest 50 transfer entries kept. Update entries (`update-available` / `update-downloaded`) live in memory only | same dir | same dir |
| `settings.json` `{ version: 1, installId (uuid v4, first run), telemetry: "unasked" \| "on" \| "off", updateCheck: true }` (WO-3 B) | same dir | same dir |
| `telemetry-queue.json` `{ version: 1, lastVersion, events: [{ name, at, props }] }`, max 500 events; empty unless telemetry is on (turning it off drops the queue) | same dir | same dir |
| `temps.json` `{ version: 1, temps: [{ path, destRoot, runId, createdAt, identity: { dev, ino, birthtimeNs } \| null }] }`: the ownership ledger (WO-3 H, H2). An entry is persisted before its temp or placeholder is created (a failed write = no claim), its identity (exact decimal strings, read through the open handle) after the create and again when the temp is sealed. Usually empty between transfers. Only one app instance per userData writes it (`requestSingleInstanceLock`), and inside it only the single active transfer | same dir | same dir |
| Renderer `localStorage`: `mt.profilesOpen` (`"1"`/`"0"`, accordion state), `mt.thumbs` (`"off"` hides the thumbnail strip; used for speed A/B only) | `.../media-transfer/Local Storage/` | `.../Media Transfer/Local Storage/` |

**Every userData JSON file is written atomically** (WO-3 R, `electron/jsonstore.ts` `writeJson`): `<file>.tmp-<pid>` in the same directory, fsync, the current file copied to `<file>.bak` if it parses, rename, directory fsync; every operation on a file (read, write, or a caller's read-modify-write via `withFile(file, tx => ...)`) runs under that file's lock and is registered from admission (WO-3 S); never call `readJson`/`writeJson`/`withFile` on the same file from inside its own `withFile` (it would wait on itself). An unparsable file is restored from `.bak` inside the lock, only if a re-read shows it still does not parse (logged once); with no usable `.bak` it is set aside as `<file>.corrupt-<time>` (logged) and the default is used; if the move fails the read fails and nothing is written; `profiles.json` is strict (the read throws, nothing written over it). Only `<file>.tmp-<pid>` of a dead process other than this one is removed; anything else under that prefix is left (logged once). The quit drains every admitted operation and then refuses new ones (`drainAndClose`); `reopenStore()` starts a new lifecycle, so a drain from an older one never closes it (RR-13). Callers honour a fail-closed read (RR-13): the telemetry queue then lives in memory only (nothing persisted), and the ledger (`LedgerUnavailableError`) claims, creates and removes nothing, so every file to copy fails with that reason and the run-start cleanup is retried at the next folder. The queue's first load is single-flight and `track()` is one locked operation. Never write a userData file with plain `fs.writeFile`.

Two dev instances share the dev `userData`. The second one cannot open the Local Storage LevelDB lock, so its `localStorage` is memory-only and isn't saved on quit. For an isolated test run, use `electron . --user-data-dir=<scratch dir>` (redirects `profiles.json` and `notifications.json` too).

## IPC (`electron/main.ts` <-> `electron/preload.ts` `window.api` <-> `src/types.ts`; keep all three in sync)

| Channel | Kind | Payload / return |
|---|---|---|
| `state:get` | invoke | `{ volumes, profiles, notifications, settings }` (notifications include the in-memory update entries) |
| `state:update` | main -> renderer, every 2 s and after writes | same shape |
| `profile:save` / `profile:delete` | invoke | profiles map; saving also removes that volume's new-drive notification |
| `notification:dismiss(volumeName)` | invoke | notification items; idempotent; writes are serialized |
| `notification:remove(id)` | invoke | notification items |
| `tree:list(absDir)` | invoke | `TreeNode[]` |
| `plan:build(origin, dest, folders, flatten)` | invoke | `PlanSummary` |
| `transfer:start` / `transfer:cancel` | invoke | `VerifyReport[]` / void |
| `transfer:progress` | main -> renderer, per 1 MB chunk | `Progress` (shape frozen) |
| `transfer:file-start` | main -> renderer, first progress event of each file | `{ absPath, name }` (source path) |
| `transfer:verify` | main -> renderer, read-back progress, throttled to ~10/s (always sent at 100 %) | `{ folderLabel, currentFile, bytesVerifiedOverall, totalBytesOverall }` |
| `transfer:done` | main -> renderer | `VerifyReport[]`, one per planned folder: `{ label, ok, reached, cancelled, tempsLeft, filesCopied, filesVerified, filesSkipped, filesFailed, failed: [{ relPath, destName, reason }] }`; `ok = filesFailed === 0`; `filesCopied` = placed (`copied-verified`) only; `stoppedError` (WO-3 I3) on the folder whose step threw (the run's other rows are kept; `transfer:start` resolves with them instead of rejecting); `reached: false` = a cancel stopped the run before that folder |
| `settings:get` / `settings:set(patch)` | invoke | `Settings`; patch `{ telemetry?: "on" \| "off", updateCheck?, resetInstallId? }`; turning telemetry on queues `telemetry_toggled`, off drops the queue |
| `update:install` | invoke | refused unless a packaged build (or `MT_TEST_UPDATE`) has a downloaded update (RR-8 #5); else finalizes an active transfer, flushes telemetry, `quitAndInstall` with relaunch. Readiness is state in `updates.ts`, independent of the bell row (RR-8 #4) |
| `shell:openExternal(url)` | invoke | opens exactly the PRIVACY.md URL, nothing else |
| `thumb:get(absPath)` | invoke | 96 px data URL or `null`. Only for source files of the active plan (never the destination). QuickLook via `nativeImage.createThumbnailFromPath`, 3 s timeout, LRU 200. |

## Telemetry, updates, release (WO-3 B, C, E)

- **Telemetry** (`electron/telemetry.ts`, `PRIVACY.md`): opt-in, asked once (modal), toggled in the gear panel. Events and props are typed in `EventProps`; props are numbers, booleans and short fixed strings only. Queue on disk, batches of <= 100 to `POST <endpoint>/v1/events`, 5 s timeout, backoff 1 min / 5 min / 30 min, 4xx batches dropped, flushed at launch, after each transfer and on quit. **Quit order** (RR-8 #1; menu, SIGINT, SIGTERM and SIGHUP all reach `before-quit`; from the first quit on, our handlers make a repeated signal a held request, RR-9 / RR-10): cancel the active transfer and await its finalization (reports, ledger, the run's bell entry and outcome event) and every pending userData write (`pendingWrites`; together bounded at 5 s, logged if exceeded), then the telemetry flush (<= 1 s) and the writes it caused (within the rest of the 5 s), then exit with `app.exit(0)`; one finalization per process: every further quit request (a second Quit, a signal, Restart to install) is held until it completes and the final quit is authorized once (RR-9); if Restart to install does not exit (the dev hook), a quit held behind it exits normally, and with none held the app stays open (RR-10); the wait is bounded at 5 s, beyond that the quit proceeds (logged) and the next run's cleanup recovers (a `before-quit` `preventDefault` + `app.quit()` stalls on SIGTERM), or, if an update is ready by then, `quitAndInstall(silent, no relaunch)`. With no transfer and an update ready the quit is left alone so electron-updater's quit path installs it; that fast path runs no telemetry flush, so queued events are sent at the next launch (RR-11; this includes a Quit after a Restart to install that did not exit, the dev hook). Consent and the anonymous id are re-read before every batch (RR-8 #2); a reset (`withIdReset`) runs after the batch in flight and before the next, so the next batch already carries the new id. Endpoint: the production URL in packaged builds; **`MT_TELEMETRY_URL=<url>`** points any build at a stage; an unpackaged build sends nothing unless it is set. Server side: `telemetry/` (own README; the PM deploys).
- **Updates** (`electron/updates.ts`): electron-updater from GitHub Releases (`publish` in package.json), packaged builds only, at launch and every 6 h while "Check for updates automatically" is on; downloads in the background, installs on quit or from the bell's "Restart to install"; errors logged, never a dialog. **`MT_TEST_UPDATE=1`** (dev hook) emits update-available then update-downloaded (3.0.1) without a network call; "Restart to install" then only logs.
- **Release (PM):** `APPLE_KEYCHAIN_PROFILE=media-transfer-notary npm run package` (electron-builder 24.13.3 notarizes through notarytool when that variable is set and `mac.notarize` is unset; the Developer ID identity is auto-discovered from the login keychain, `CSC_NAME` pins it if there are several; `CSC_IDENTITY_AUTO_DISCOVERY=false` builds unsigned). Then `gh release create v<version> release/Media-Transfer-<version>-arm64.dmg release/Media-Transfer-<version>-arm64-mac.zip release/*.blockmap release/latest-mac.yml --title "Media Transfer <version>" --notes "..."`. **Never rename an asset:** `latest-mac.yml` names them exactly; `artifactName` has no spaces because GitHub turns a space in an asset name into a dot, which would break the updater's lookup (the v2.0.0 asset was renamed by hand; v2.0.0 has no updater, so v3.0.0 is the first release it can track).
- Hardened runtime + `build/entitlements.mac.plist` (allow-jit, allow-unsigned-executable-memory, allow-dyld-environment-variables, disable-library-validation); targets dmg + zip.

## New-drive notification rules

A volume shows inline under "New drive detected" only while it is mounted, unlabeled and not dismissed. × creates the persisted entry; it survives unplug/replug and relaunch. The bell badge = number of entries. Label is enabled only while mounted. Remove drops the entry (if the drive is still mounted and unlabeled, its card comes back). Saving a profile removes the entry.

## Verified transfer (v3.0)

- **Per file** (`executePlan` in `electron/transfer.ts`): copy into `<final dir>/<basename>.mtpart` while hashing (SHA-256, `node:crypto`, each chunk hashed in a `setImmediate` so it overlaps the next card read), then read the temp back and hash it in the worker thread of `electron/hasher.ts` (inline worker source, nothing extra to package). Match -> `utimes`, then the final name (below) via `noClobberRename`. Mismatch -> copy once more and re-check; a second mismatch removes the temp, and the file is `failed`. Copy and read-back are a one-deep pipeline: file i copies while file i-1 is read back; two files that share a temp name are never in flight together.
- **Naming rule** (`placeVerified`): the plain name if it is free; identical content already there (same size + SHA-256) is a skip and our temp is dropped; otherwise `<stem>-<hash8><ext>` (first 8 hex of the SHA-256) under the same rules; if both names hold different files the file fails. With flatten, the first of two same-named files copied takes the plain name.
- **Skip** (`buildPlan`): size + mtime (2 s) match under the plain name or any `<stem>-xxxxxxxx<ext>` sibling. `walk` ignores dot-entries (so `.media-transfer/`) and `*.mtpart`.
- **Phases** (renderer): `copying -> verifying -> done`. `verifying` = every byte copied, last read-backs pending. The read-back bar shows bytes read back / total throughout.
- **Report**: `<destRoot>/.media-transfer/transfer-<YYYYMMDD-HHMMSS>.json` per reached folder after every transfer: `{ version: 1, app, cancelled?: true, tempsLeft?: n, startedAt, finishedAt, origin, destination, flatten, files: [{ source, dest, size, mtime, sha256?, status, reason? }] }`, `status` = `copied-verified` | `skipped` | `failed` | `cancelled` (the file(s) in flight when cancel came) | `not-started` (a cancelled folder's planned files the cancel never reached, WO-3 I3). Plan skips carry no hash. Written with `noClobberWriteFile` at the end of the run (WO-3 H3), so every report of a cancelled run carries `cancelled: true`; a same-second name gets `-2`, `-3`, ... Folders a cancel never reached get no report.
- **Cancel** is checked per 1 MB chunk (copy and read-back), after every await before publication (`statOrNull`, the exFAT claim/open/identity steps) and inside `noClobberRename` immediately before `link` / `rename`, and inside the collision hash; it returns at once. Once the in-flight copy and read-back have returned, this run's temps and placeholders are removed (identity match), so a cancel leaves no `.mtpart` and no app-created empty file under a final name (a cancel right after the exFAT placeholder is disarmed removes it by the identity recorded through its handle, or re-arms the entry). Cancellation is tracked for the run, sampled once more after the last publication, and every reached folder's row says cancelled. A removal that fails keeps its ledger entry and is counted in `tempsLeft` (panel: "Cleanup incomplete: n temporary files left"); the next transfer to that folder retries it.
- **Identity per volume** (WO-3 K): at the start of each folder, `noClobberProbe` runs a probe file under `<destRoot>/.media-transfer/` through a temp's life (create, write, close, set times through a handle, rename), stat'ing it through the handle and by path after each step, then removes it. It decides the volume's profile: `handleStable` (APFS yes; exFAT no: exFAT reports a synthetic negative inode while any handle is open and for ~5-10 ms after the last close, and empty files never get a real one), `useBirth` (APFS no: setting the source mtime moves birthtime; exFAT yes) and `removalEnabled` (dev + ino stable after close; if not, nothing the app left there is ever removed). On handle-unstable volumes identity is recorded by path after the close once the inode settled (`lstatSettled`, off the copy path; reads, checks and removals of a temp wait for it via `noClobberSettled`). Main logs `volume probe <folder>: {profile}`. The probe (WO-3 K3) resets the destination to CAUTIOUS first and stays CAUTIOUS on any failure; its file is a ledger entry for its whole life, published with `noClobberRename` onto an exclusively reserved second name, and removed on every exit by an exact dev + ino match (what can't be removed stays recorded and counts in tempsLeft). `lstatSettled` fails closed (`UnsettledError` at the deadline: no identity, the entry is kept and counted); placement-path waits sample cancellation. On handle-unstable volumes a provisional identity `{ dev, birthtimeNs }` is persisted by path right after the exclusive create, before the first write (WO-3 K2); it authorizes only removing that never-sealed `*.mtpart` at a later run's cleanup when lstat matches dev + birthtime, and the full identity replaces it. **Any change to `noclobber.ts` or `transfer.ts` needs the in-app full set on an exFAT image and on APFS as evidence** (the harness alone missed this).
- **Ownership** (`noclobber.ts`, WO-3 H + H2) is identity, not a path. Every removal (start-of-run cleanup, cancel drop, failed-file drop) `lstat`s the path and unlinks only when dev + ino + birthtime (ns) equal the entry's identity; no identity or a different file = the file is left alone and the entry dropped. A temp name that exists and is not ours = foreign: never replaced or removed, that source file is `failed` with "temp name taken by an unknown file". Identity is re-recorded through the temp's handle after the first 1 MB is written and when the copy ends (`seal()`): exFAT gives an empty file a synthetic inode, and setting the temp's mtime moves its birthtime (so times are set through the handle, `noClobberSetTimes`). Placement: `link(temp, final)` where hard links work; on exFAT (`ENOTSUP`) the final name is reserved with an exclusive placeholder (claimed first), its entry is disarmed (identity cleared) before publication so a crash can never authorize deleting the placed file, its identity is re-checked through the open handle against `lstat(final)`, then `rename(temp, final)`. Once `link`/`rename` succeeds the file is `copied-verified`; later bookkeeping failures are logged and their entries kept. Threat model: the app assumes it is the only writer to the destination folder during a transfer (another writer between the last identity check and the rename call is out of scope). The pipeline settles when two files' destinations are aliases (`aliasKey`: NFD + lower case); an `EEXIST` on a temp of this run waits for the file in flight instead of removing anything.
- **Test hook** `MT_TEST_CORRUPT=<basename>` (env var, dev only): flips byte 0 of that file's temp before every read-back, so both attempts mismatch and the file fails. No effect without the variable. `MT_TEST_CORRUPT=DSC00002.JPG npx electron . --user-data-dir=<scratch>`.
- **More dev-only hooks** (env, no effect unset): `MT_TEST_LEDGER_FAIL=1` makes ledger writes fail right after each publication (the file must still be `copied-verified`); `MT_TEST_REMOVE_FAIL=1` makes removals of owned temps and placeholders fail with `EPERM` (cleanup-incomplete path); `MT_TEST_CANCEL_AT_DISARM=1` cancels the run right after an exFAT placeholder is disarmed. `MT_TEST_CRASH_BEFORE_RENAME=<basename>` (e.g. `notifications.json`) SIGKILLs the process after that userData file's tmp is written and fsync'ed, before the rename (the previous content must survive). `MT_TEST_HOLD_RECOVERY_MS=<ms>` holds a recovering read after it read the `.bak`; `MT_TEST_SETASIDE_FAIL=1` makes moving an unparsable file aside fail (EIO); `MT_TEST_HOLD_SAVE_READ_MS=<ms>` holds a profile save before its read (WO-3 S). `MT_TEST_HOLD_QUEUE_READ_MS=<ms>` holds the first telemetry-queue read (WO-3 T). `MT_TEST_FINALIZE_DELAY_MS=<ms>` stretches the quit's finalization (to show a second quit request being held, RR-9). `MT_TEST_PROBE_FAIL=write|stat-after-write|utimes|rename|stat-after-publish` makes the volume probe fail at that step (with `MT_TEST_REMOVE_FAIL=1` its files can't be removed either) (the destination then runs CAUTIOUS: identity by path, no removals).
- **Known limit**: the read-back may be served from the macOS file cache; verification proves what macOS reports it wrote, not the medium.

## Thumbnail conveyor

`src/ThumbConveyor.tsx` renders only while `phase === 'copying'`. It requests at most one thumbnail at a time and spawns at most 2 tiles/s; the newest pending file wins, and skipped or `null` files get no tile. The copier never awaits any of it. Tiles cross the strip in 5 s (CSS `@keyframes conveyor`).

## Test rig (disk images only)

Keep the `.dmg` files in the session scratchpad, not `~`. **Volume names are per seat:** the Tester's rig also mounts `TestCard` / `TestDest*`, so the Dev seat uses its own prefix (`DevH*` in WO-3 H) and checks `hdiutil info` before attaching or detaching anything. Claude Code's safety check refuses `rm -r` of a folder at the top of any volume (`/Volumes/TestDest/TestCard`), so clear rig destinations by their deeper paths (`.../TestCard/DCIM`) or use a fresh image. `team/evidence/dev/wo-2/harness.ts` drives `buildPlan` + `executePlan` headless against `TestCard` -> `TestDest*` only.

```sh
hdiutil create -size 1500m -fs ExFAT -volname TestCard <scratch>/testcard.dmg && hdiutil attach <scratch>/testcard.dmg
hdiutil create -size 3000m -fs APFS  -volname TestDest <scratch>/testdest.dmg && hdiutil attach <scratch>/testdest.dmg
mkdir -p /Volumes/TestCard/DCIM/100MSDCF /Volumes/TestCard/PRIVATE/M4ROOT/{CLIP,THMBNL}
# JPGs: ffmpeg -f lavfi -i "testsrc2=size=3000x2000:rate=1,noise=alls=40:allf=t" -frames:v 24 -q:v 2 frame%02d.jpg
# MP4:  ffmpeg -f lavfi -i "mandelbrot=size=1920x1080:rate=30" -t 6 -c:v libx264 -b:v 60M clip.mp4
```

A local image copies at ~1-2 GB/s, so a transfer is over in about a second. For card-like speed, serve the card image over a throttled local HTTP server and attach it read-only: `hdiutil attach -readonly http://127.0.0.1:8765/tmp-testcard.dmg` (server: `team/evidence/dev/wo-1/C/slowserve.mjs <file> 8765 120`). Label the images in the app, delete the test profiles afterwards, then `hdiutil detach /Volumes/TestCard /Volumes/TestDest` and delete the `.dmg` files the same day.

Driving the running app: launch with `--remote-debugging-port=9229` and use `team/evidence/dev/wo-1/cdp.mjs` (`eval`, `shot`, `cast`). Screenshots only paint while the window is frontmost.
