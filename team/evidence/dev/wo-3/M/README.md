# WO-3 item M evidence: RR-8 findings (Dev, Basalt, 2026-10-24)

Rung: **tested**. Seat-unique rig: `DevMCard` (exFAT, DCIM 3 JPG + CLIP 3 MP4, served read-only at 120 MB/s on :8771) -> fresh exFAT images `DevMDest<n>`; app = `file://` build, isolated userData, CDP :9242 (`m.sh`, `start.js`). The Tester's VR-6 apps and `Ts*` images were running meanwhile and untouched; for that reason "menu quit" was exercised as SIGINT (Electron turns it into `app.quit()`, the same `before-quit` path as the Quit menu item) instead of a quit Apple event to "Electron", which could have reached the Tester's instance.

| RR-8 | Fix | Evidence |
|---|---|---|
| #1 quit during a transfer (P1) | `finalizeBeforeExit()` in `main.ts`: cancel, await the run's finalization (reports + ledger; bounded 5 s, logged if exceeded), telemetry flush <= 1 s, then exit or, with an update ready, `quitAndInstall` silent without relaunch. Used by `before-quit` (menu, SIGINT, SIGTERM) and by "Restart to install" | `01-quit-sigTERM-mid-transfer-exFAT.txt`, `02-quit-sigINT-mid-transfer-exFAT.txt`: signal 1 s into a transfer; exited in 0.08 s / 0.14 s after "active transfer cancelled and finalized before exit"; both folders' reports exist (`cancelled: true`; CLIP `copied-verified, cancelled, not-started`); ledger empty, 0 `.mtpart`; the next run copies the rest and verifies |
| #2 reset during a flush (P1) | `sendAll` re-reads consent and `installId` before every batch (stops on withdrawn consent; on a new id it stops and re-flushes); `withIdReset` serializes the reset after the batch in flight and holds a gate the next batch waits on | `03-reset-during-flush.txt`: 200 events queued, stub holds the first response 3 s, reset 200 ms into the flush: reset resolves after 3035 ms (waited for the batch); request 1 (100 events) old id, requests 2 (100) and 3 (1) the new id; queue empty. A first version without the gate sent request 2 with the old id: fixed |
| #3 prototype names | `EVENT_PROPS` is a `Map` of `Set`s built from own properties | `07-validate-prototype-names.txt`: events named `toString`, `constructor`, `__proto__`, `hasOwnProperty`, `valueOf` and props named `toString`, `__proto__` -> 400 |
| #4 readiness independent of the bell | `readyVersion` in `updates.ts`; removing the row changes nothing; re-checked right before the deferred exit | `04-update-guard-and-row-removal.txt`: row removed (0 update rows), quit -> "update waiting and no transfer: the normal quit path installs it"; `06-quit-mid-transfer-with-update-ready.txt`: SIGTERM during a transfer with an update ready -> finalized first, then `quitAndInstall(isSilent=true, isForceRunAfter=false)`, exit in 0.08 s, both reports, ledger empty |
| #5 installUpdate guard | `update:install` throws unless `updateReady()` (packaged or the dev hook, with a downloaded update) | `04-…`: before the download -> rejected "No downloaded update to install"; `05-install-after-download.txt`: after it -> resolved, install logged |

Found while testing and fixed: with an update ready, the deferred quit handed over to `installNow(false)`, which under the dev hook only logs, so the app never exited; `installNow` now returns whether it quits and the caller exits otherwise.
