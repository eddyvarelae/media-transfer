Found and fixed while producing this evidence (all in this commit):
- **`utimes` moves the birthtime.** Setting the temp's mtime to the card's (earlier) mtime makes macOS pull its birthtime back, so a temp no longer matched its own identity. Times are now set through the temp's handle (`noClobberSetTimes`), which re-records the identity.
- **exFAT inodes change.** An empty file gets a synthetic inode (`-3`, `-6`…) and the real one at the first write. The identity is re-recorded through the handle after the first 1 MB (`drain`) and when the copy ends (`seal()`). `05-crash-temp-recognized.txt`: crash 10 MB into B (unplug-like), nobody touches the temp; next run recognizes and removes it, both files verified, no `.mtpart` (APFS and exFAT). A crash before the first 1 MB on exFAT leaves a temp the next run cannot recognize: it is left alone and that one file fails until it is deleted (the safe side).
- **`FileHandle.close()` waits for its stream.** `seal()` destroys the finished stream first; on cancel, `copyHashing` no longer destroys the stream itself (the old order reported an interrupted file as failed, "file closed").
